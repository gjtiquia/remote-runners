# Issue tracker: GitHub

Issues and specs live in gjtiquia/remote-runners on GitHub.
Use the gh CLI, explicitly targeting this repository.

Check authentication before operations. Read existing items before
editing them, and verify mutations afterward. Use temporary body files
for multiline Markdown.

Publishing a spec means creating a GitHub issue.
Fetching a ticket means reading its body, labels, and relevant comments.

PRs as a request surface: no.

Use native GitHub sub-issues and blocking dependencies when splitting
work. If unavailable, use parent task lists and explicit blocking links.
